# mcp-check

作業は「検証用リポジトリを新しく作り、ブラウザだけで5つのファイルを格納して、Claude Code から MCP ツールが見えるかを確かめる」という流れです。必要なファイルは `mcp_check.zip` にまとめました。こちらの環境で MCP クライアントから3つのツールを呼び出し、集計結果が返ることまで確認済みです。

## 前提:演習用リポジトリには直接入れない

`CloudeCodeTest` は受講者が Fork するテンプレートなので、検証には**別のリポジトリ**を使います。理由は2つあります。

- 検証には仮の集計関数(`src/analysis.py`)が必要です。これがテンプレートに入ると、第2段階で受講者が TDD を行うときに、最初から実装がある状態になり、Red(テストの失敗)が起きません
- `.mcp.json` はセッションの開始時にしか読み込まれません。ブランチを分けて検証すると、どのブランチの `.mcp.json` が読まれたのかを判別しにくくなります

## 手順

### 手順0:クラウド環境に `mcp` を導入する(最初に実施)

MCP サーバーはセッションの開始時に起動されます。その時点で `mcp` パッケージが入っていないと、サーバーの起動に失敗し、ツールが表示されません。

1. claude.ai/code を開き、メッセージ入力欄の上の行にある**雲のアイコン(環境名)**をクリックします
2. **Cloud** を選び、使用する環境にカーソルを合わせて、右に出る**歯車アイコン**をクリックします
3. **Setup script** 欄に次の内容を入力して保存します

```bash
#!/bin/bash
pip install -q streamlit pandas pytest "mcp<2" || true
```

Owner が組織共有環境をまだ作っていない段階では、ご自身の個人環境(Default)にこの設定をして検証してください。

### 手順1:検証用リポジトリを作る(GitHub)

1. GitHub 右上の **+** → **New repository**
2. Repository name に `mcp-check` と入力します
3. **Add a README file** にチェックを入れます(空のリポジトリだとファイルのアップロード画面が出ないため)
4. **Create repository** をクリックします

Private で作る場合は、Claude GitHub App がそのリポジトリへのアクセスを許可されている必要があります(GitHub の Settings → Applications → Claude → Repository access)。Public であればこの確認は不要です。

### 手順2:ファイルを格納する(GitHub の画面上で)

`mcp_check.zip` を PC で展開してから、次の2つの操作を行います。

**(a)フォルダとファイルのアップロード**

1. リポジトリの画面で **Add file** → **Upload files**
2. 展開したフォルダから、`mcp_server`、`src`、`data` の3フォルダと `requirements.txt` を、画面にまとめてドラッグ&ドロップします(フォルダ構造はそのまま保たれます)
3. 下部の **Commit changes** をクリックします

**(b)`.mcp.json` の作成**

`.` で始まるファイルは Windows や macOS で非表示になることが多く、ドラッグできない場合があるため、画面上で直接作ります。

1. **Add file** → **Create new file**
2. ファイル名の欄に `.mcp.json` と入力します
3. 本文に次の内容を貼り付けて、**Commit changes** をクリックします

```json
{
  "mcpServers": {
    "expense-analysis": {
      "type": "stdio",
      "command": "python3",
      "args": ["${CLAUDE_PROJECT_DIR:-.}/mcp_server/server.py"],
      "env": {
        "EXPENSE_CSV": "${CLAUDE_PROJECT_DIR:-.}/data/expenses.csv"
      }
    }
  }
}
```

**格納後の構成(確認用)**

```text
mcp-check/
├── .mcp.json
├── README.md
├── requirements.txt
├── data/
│   └── expenses.csv      … 疑似データ5件(3部署、9月・10月)
├── mcp_server/
│   └── server.py         … MCPサーバー本体
└── src/
    └── analysis.py       … 集計関数の仮実装(検証専用)
```

### 手順3:Claude Code で確認する

1. claude.ai/code でリポジトリ `mcp-check` を選び、手順0で設定した環境が選ばれていることを確認します
2. 次の指示を送ります

```text
利用可能なMCPツールを列挙してください。
続いて expense-analysis の total_by_department を呼び出し、結果をそのまま表示してください。
```

3. 次の結果になれば成功です

| 確認点 | 期待値 |
|---|---|
| ツール名 | `mcp__expense-analysis__total_by_department`、`..._total_by_month`、`..._total_by_transport` の3つ |
| 部署別合計 | 企画部 14,250円、営業部 1,450円、総務部 8,000円 |

4. 余力があれば、自然言語での問い合わせも確認します(例:「部署ごとの交通費の合計を教えて」)。Claude がツール名を指定されなくても自分でツールを選んで呼び出せば、第4段階で受講者に体験させたい動作が成立しています

### 手順4:結果の判定

| 結果 | 原因の見立て | 対応 |
|---|---|---|
| 成功 | — | 第4段階を受講者による体験として実施できます |
| ツールが1つも表示されない | `.mcp.json` がクラウドセッションで読み込まれていない(前に挙げた不具合報告と同じ現象) | 第4段階は講師デモに切り替えます |
| ツールは表示されるが、呼び出すとエラーになる | `mcp` 未導入、またはファイルの格納場所の誤り | Claude に「`python3 -c "import mcp; print(mcp.__file__)"` を実行して」と指示し、導入状況を確認します |

## 検証が成功した後の判断事項

演習テンプレート(`CloudeCodeTest`)にどう組み込むかは、次の2点を決める必要があります。

1. **`.mcp.json` を入れる時期**: テンプレートに最初から入れておくと、第1段階・第2段階では `src/analysis.py` がまだないため、セッションを開始するたびに MCP サーバーの起動が失敗します。この失敗表示は、非エンジニアの受講者を混乱させるおそれがあります。第4段階の冒頭で受講者が追加する(または講師が配布する)方式を推奨します
2. **分析データの供給方法**: 第1段階のアプリからダウンロードした CSV を受講者が `data/` に格納する方式にするか、運営が疑似データを配布する方式にするかを決める必要があります。前者は題材のつながりが明確ですが、件数が少ないと分析結果の差が見えにくくなります
